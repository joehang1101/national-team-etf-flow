# 数据质量与归因研究版本

## 模块

`refresh.py`只负责调度与命令行；`fetch.py`负责取数及缓存合并；`calculations.py`负责单只ETF计算；`compute.py`汇总；`render.py`生成网页。`runtime.py`提供路径、时间、文件操作；`provenance.py`处理来源与修复；`exports.py`输出CSV；`attribution.py`处理披露锚点和共同因子研究。

## 来源与旧缓存修复

份额缓存升级到schema 2，数值仍在 `shares[日期][代码]`，配套记录在 `share_meta[日期][代码]`，包括source、observed_at、source_url、replaces_source、previous_value。

- `sse` / `szse`：本次按官方日期重新取得的记录。
- `fallback` / `eastmoney_f84`：兜底记录，不参与净申赎计算；官方数据可覆盖它。
- `legacy_unknown`：旧版本没有来源记录，不能事后声称它必定是官方值；保留其估算，但不进入来源核验研究样本。

本版本没有实时f84采集入口。最新日显示“可计算数”和“两日均有官方来源且可计算数”两个指标。旧数据不会被整体删除、冒充官方，历史记录即使不再属于当前观察池也保留。

联网更新默认额外修复8个旧日期（`--repair-days 8`），不受最近12天限制；兜底优先，失败日期按尝试时间轮换，不会因为失败一次就标记成功。`--repair-days 0`可以暂停旧历史修复。可用 `--require-official` 阻止最新日来源覆盖不足的报表发布。历史缺口与未知来源需逐步修复，不表示一次运行能完成全部历史验证。

沪深请求按日期对齐；深市旧修复日期和近期日期会重新分批，避免跨几年拼成一次超过6个月限制的区间请求。

## 折算

确认折算配置位于 `config/events.json`。一条事件需要代码、日期、factor、新旧份额换算因子、verified、公告链接及published_at。factor表示“1份旧份额折为多少份新份额”。实际字段示例：

```json
{"code":"示例代码","date":"20261113","factor":1.002,"verified":true,
 "source_url":"https://发行人官方公告地址","published_at":"2026-11-12"}
```

这是格式示例，不是真实事件，不写入实际配置。

有确认事件时：`净申赎份额 = 当日份额 - 上日份额 × factor`，再乘当日净值。这样不会把折算日同时发生的真实申赎一起清零。

没有公告时仅作疑似标记，不推断为真实零。大幅反向变化检查份额比×净值比是否接近1；小幅变化采用更严格的近倒数条件。普通申赎也可能恰逢反向价格变动，启发式会误报或漏报，因此不能替代事件公告。疑似事件金额留空，等待核验。已确认但事后才公开的事件可以用于修订历史，但其公告时间单独导出，归因当日训练不使用未来公告。

CSV为空表示缺失，0表示真实零。金额单位是人民币元，网页展示亿元。`backtest_eligible`只表示相邻官方份额及价格可计算，**不代表时点回测资格**。`pit_eligible=false`和清单中的 `point_in_time_backtest_ready=false`表明当前是事后修订数据集：旧净值和行情尚无完整首次发布时间，观察池历史成员也未完全核验。要做严格回测，需增加不可覆盖的逐次采集快照、发布延迟、交易执行时点和成本模型。

指数源当前只区分live/cache混合及560050代理，未伪造每根历史K线的供应商身份。

## 披露锚点

`config/anchors.json`先接入510300两个报告期、两家汇金实体的4条记录：2025半年报及2025年报。记录报告期、实际公告日期、单位、持有人、章节、页码、链接；年报已下载校验文件摘要，半年报使用上交所原报告的已索引表格核验，原PDF本机下载受证书问题阻断，不填写虚构文件摘要。

两家主体分别记录，不能把汇金投资和汇金资管混成同一实体。前十大未出现不是持仓为0；本版本不会自动把未知账户当作汇金系。

锚点区间函数只比较同一主体且可比份额单位的端点净变化，并记录两端报告均公开后才可得的available_at。同一端点数值不变也可能有期间往返交易。缺少两端或折算口径不一致时不强行比较，更不会线性插值生成每日机构买卖。

条件容量边界还提供一种保守区间：设最近已公开且同报告期的汇金锚点合计为H，当前ETF总份额为S。在“份额单位可比、没有未记录折算”的条件下，当前持有份额只能位于[0,S]，相对锚点变化位于[-H,S-H]；若S小于H，至少有H-S的持仓减少。这个减少可通过二级市场卖出发生，不能解释为ETF净赎回，也不能定位到某一天。当前数值只是条件边界，不是机构实际持仓点估计。

## 共同因子与证据等级

对照需提供已核对的报告链接、证据可得日（`control_evidence_available_at`），并设置 `control_status=reviewed` 才可使用。证据可得日与基金观察池的known_from分开，避免因审查发生较晚而丢失早期基金历史。每日至少3只可计算且来源合格的对照，以其申赎额/上日资产规模的中位数作为共同情绪因子。

每只候选ETF用此前最多60个合格样本做OLS，至少20个训练样本，估计 `候选申赎率 = alpha + beta × 共同因子 + 残差`。当天数据不进入当天参数拟合。输出残差的历史异常分位，与身份置信度分开。

- 数据、对照或训练不足：证据不足，不出概率。
- 可计算残差：先区分R²不足、剔除对照后方向不稳、显著异常、未见显著偏离。低证据判断只描述统计关系。
- 异常分位至少95%、拟合R²至少0.1，且至少3只对照的机构身份污染已被单独排除，并有当时已公开、报告期距当日不超过366天的持有人锚点：研究模式标记疑似增量申购/赎回，证据最多“中”。

这些阈值是研究规则，没有被标注样本校准，identity_probability始终为空。当前3只代理通过的是市场因子适用性审查，不是机构身份洁净性审查，因此可以输出统计判断，但不能提升机构归因证据等级。敏感度检查会逐只剔除代理，同时重建历史因子并重新拟合，而不只是修改当日因子值。不能把模型残差直接解释为机构金额或将其用于已验证的未来收益预测。
